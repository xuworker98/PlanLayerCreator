# 奥维扇区纯文字标签解决方案

## 一、最终结论

经过对实际可用KMZ样本的只读拆解，已经确认：

> 一份完全标准的KML/KMZ可以同时在Google Earth和奥维互动地图中显示扇区文字标签，并且不显示图钉。

不需要奥维私有扩展、`gx:`、ExtendedData特殊字段、透明PNG、data URI、`IconStyle scale=0`、奥维运行时接口、OVKML或两套不同成果。

真正有效的标签结构是：

- 标签仍使用标准Point Placemark承载坐标和`name`。
- 标签引用一个文档级共享Style。
- 共享Style中明确存在IconStyle。
- IconStyle内只有一个完全为空的Icon元素，即`<Icon/>`。
- 不写`href`，不写透明图片，不打包图标资源，也不设置IconStyle的`scale`。
- LabelStyle单独控制文字大小和颜色。

此前“标准KML不能让奥维显示纯文字无图钉”的判断已经被真实样本推翻。准确结论应改为：奥维不可靠支持透明图片、零缩放等隐藏方法，但能够识别空Icon为“无图标”。

## 二、实证样本

验证文件：

`F:\南宁5G规划扇区图层.kmz`

验证日期：2026年8月28日。

用户已经确认它在Google Earth和奥维互动地图中均能正常显示扇区名称且没有图钉。

### 2.1 KMZ结构

- KMZ大小为62,862字节，内部只有一个239,339字节的KML文件。
- KML只使用`http://www.opengis.net/kml/2.2`标准命名空间。
- 没有PNG、图标或其他附属资源。
- 没有`gx:`、奥维私有元素、ExtendedData、StyleMap或矢量化文字。
- 包含`基站名称`和`基站扇区`两个Folder。
- 包含117个标签Point和117个扇区Polygon，名称一一对应。
- 标签和扇区分别引用两个共享Style。

### 2.2 已验证的标签Style

```xml
<Style id="btsname">
  <IconStyle>
    <Icon />
  </IconStyle>
  <LabelStyle>
    <scale>0.6</scale>
    <color>FFc0ffff</color>
  </LabelStyle>
</Style>
```

关键是空`Icon`。样本中的`LabelStyle scale=0.6`只控制文字大小，不负责隐藏图标。

### 2.3 已验证的标签Point

```xml
<Placemark>
  <name>小区名称</name>
  <styleUrl>#btsname</styleUrl>
  <Point>
    <extrude>1</extrude>
    <altitudeMode>clampToGround</altitudeMode>
    <coordinates>经度,纬度,5</coordinates>
  </Point>
</Placemark>
```

样本的标签Point位于扇区中心方向的外沿。统计显示标签距站点约80米，基本等于扇区半径。

位置、5米高度、extrude和clampToGround可能影响标签摆放，但隐藏图钉的决定性结构是空Icon。首次实现应完整复刻样本，再通过对照试验精简非必要字段。

## 三、工作原理

Google Earth和奥维都依赖Point Placemark的`name`显示地图文字。

当前PlanLayerCreator使用透明PNG data URI并把IconStyle比例设为0。这种写法仍表示“存在一个图标，只是该图标透明或缩放为0”。奥维导入时仍可能把它当作图标标签，并回退成默认图钉。

网优图层工具表达的是另一种语义：这个Point拥有IconStyle，但Icon对象本身没有任何图标来源。空`<Icon/>`没有`href`，也没有透明图片。奥维将其识别为“无图标”，同时继续读取Point的`name`并按LabelStyle显示文字。Google Earth也能显示相同文字。

## 四、与当前PlanLayerCreator的差异

| 项目 | 网优工具成功样本 | 当前PlanLayerCreator |
|---|---|---|
| 标签载体 | Point Placemark | Point Placemark |
| 图标定义 | 完全为空的`<Icon/>` | 透明PNG data URI |
| Icon href | 不存在 | 存在data URI |
| IconStyle scale | 不设置 | 设置为0 |
| 标签Style | 所有标签共用一个Style | simplekml通常生成对象样式 |
| LabelStyle scale | 0.6 | 1.2 |
| 标签位置 | 扇区中心方向外沿 | 扇区半径一半处 |
| 私有扩展 | 无 | 无 |

最关键的整改是删除透明图标和零缩放，生成完全为空的Icon元素。共享Style也是成功样本的一部分，并可显著减少重复XML，首次修复应一起采用。

## 五、标签字号方案

样本使用`LabelStyle scale=0.6`，用户已经明确认为偏小，因此PlanLayerCreator不应照抄该字号。

字号与空Icon相互独立：

- 空`<Icon/>`负责不显示图钉。
- `LabelStyle scale`只负责文字大小。

产品建议：

- 默认标签比例保持为`1.2`，优先满足站点评审可读性。
- 在扇区样式区增加“标签大小”控件。
- 建议可调范围为0.5到3.0。
- 首次实机测试比较0.8、1.0、1.2和1.5。
- Google Earth与奥维使用同一个比例，确保唯一文件的一致性。

若两款软件对同一比例的视觉大小略有不同，应选择双方均可接受的默认值，不得因此恢复双文件输出。

## 六、PlanLayerCreator实施方案

### 6.1 保持单一成果

软件继续只生成用户选择的一份KML或KMZ，该文件同时供Google Earth和奥维使用。

不得增加以下强制流程：

- 生成Google Earth版和奥维版两份文件。
- 生成KML时要求奥维正在运行。
- 生成后通过奥维接口再次写入标签。
- 要求用户导入后手工批量修改样式。

### 6.2 KML结构

建议文档级结构：

1. 一个扇区共享Style。
2. 一个标签共享Style。
3. 一个标签Folder。
4. 一个扇区Folder。
5. 每个扇区一个Polygon Placemark。
6. 每个标签一个同名Point Placemark。

标签Style必须满足：

- 明确包含IconStyle和空Icon。
- 空Icon中不包含href。
- IconStyle不写scale、color、heading、hotSpot等无关默认字段。
- LabelStyle写入用户选择的颜色和比例。

### 6.3 控制最终XML

simplekml在设置Icon对象时可能自动输出`scale=1`、`heading=0`、`colorMode=normal`或空`href`子元素。

首次实现必须以成功样本的最终XML为准，避免生成：

- `<Icon><href></href></Icon>`；
- 带默认scale的IconStyle；
- 指向透明图片的Icon；
- data URI或失效图标地址。

如果simplekml无法精确生成，应使用结构化XML写出共享Style，不能继续依赖透明图片兜底。

### 6.4 标签位置

成功样本把文字放在扇区外沿，当前软件放在半径一半位置。建议把标签位置改成可配置比例：

- 默认先采用成功样本的约1.0倍半径。
- 可调范围建议为0.5到1.2倍半径。
- 检查密集站点文字遮挡和可读性。

位置调整不得改变空Icon结构。

### 6.5 属性信息

成功样本没有ExtendedData，但PlanLayerCreator可以继续在扇区Polygon中保存属性表。标签Point建议保持精简，只保存name、styleUrl、Point坐标和必要高度模式。

## 七、不再采用的路线

- `IconStyle scale=0`或极小比例。
- 透明PNG、打包透明PNG、透明data URI或图标透明色。
- 空字符串href或失效URL碰运气。
- `gx:`、ExtendedData或奥维私有字段猜测。
- 奥维运行时接口作为必要条件。
- OVKML/OVKMZ双输出。
- 把文字转换成Polygon或LineString轮廓。

奥维接口和OVKML可以作为未来独立功能研究，但不属于本问题主方案，也不得改变“只生成一份标准KML/KMZ”的产品要求。

## 八、测试与验收

### 8.1 自动结构检查

- KML可被标准XML解析器解析，只使用标准KML 2.2命名空间。
- Point数量与成功扇区数量一致，Point与Polygon名称一一对应。
- 所有标签引用同一个标签Style。
- 标签Style包含空Icon，不存在href和IconStyle scale。
- 文件中不存在透明PNG data URI。
- LabelStyle比例等于用户设置值，默认值为1.2。

### 8.2 Google Earth实机验收

- 扇区面和每个扇区名称正常显示。
- 不显示图钉或其他点图标。
- 默认字号比成功样本的0.6更大，适合站点评审。
- 标签和扇区Folder可独立控制显隐。

### 8.3 奥维实机验收

- 使用同一份KML或KMZ直接导入。
- 扇区面和每个扇区名称正常显示。
- 不出现黄色大图钉、默认图钉或透明占位。
- 无需导入后手工改样式，无需启动接口或辅助程序。
- 标签字号清晰可读。

### 8.4 对照试验

第一次修复保留三个最小测试文件：

1. 成功样本结构：空Icon、无IconStyle scale。
2. 当前失败结构：透明data URI、IconStyle scale=0。
3. 仅把LabelStyle比例改为1.2的空Icon结构。

第三个文件必须证明字号从0.6提高到1.2不会破坏奥维的空Icon隐藏效果。

## 九、Hermes执行要求

1. 在测试中固化成功KMZ的共享Style和对象结构。
2. 将标签Style改为文档级共享Style。
3. 输出完全为空且无href的Icon。
4. 删除透明PNG常量、data URI及IconStyle scale=0逻辑。
5. LabelStyle默认比例保持1.2，并加入可调参数。
6. 检查最终KML文本，不能只检查源代码。
7. 生成最小文件并在Google Earth和奥维实机验证。
8. 实机通过后再进入全面整改和打包流程。

若序列化库自动添加了与成功样本不同的Icon字段，应继续修正最终输出结构，不得宣称完成。

## 十、最终产品定义

最终产品只生成一份标准KML或KMZ，其中同时包含扇区Polygon、纯文字标签Point、共享扇区Style、共享空Icon标签Style以及用户可调且默认清晰可读的LabelStyle。

用户不需要理解内部特殊写法，不需要打开奥维等待生成，也不需要接收两套成果。
